# БРС рядом

Первый запуск, Mini App, GitHub и Raspberry Pi: [пошаговый гайд](START_HERE.md).

Свой аналог студенческого бота БРС ЮФУ: Telegram-бот и Mini App с единым Python-сервером. Рассчитан на Raspberry Pi OS **64-bit**, Python 3.11+ (Docker — Python 3.12). На устройстве не нужны Node.js, PostgreSQL или Redis. Статический интерфейс без сборки. Независимый проект, не официальный сервис ЮФУ.

## Что реализовано

- Вход по токену с `https://grade.sfedu.ru/student/authtokenget`. Пароль ЮФУ не требуется.
- Предметы и баллы по семестрам; учебная карта с работами и журнал посещаемости.
- Уведомления об изменении **итогового балла предмета**, включая уменьшение и сброс оценки. Начальная загрузка не создаёт уведомлений. Изменения работ при неизменном итоге не отслеживаются фоном.
- История с момента подключения (до 1000 доставленных событий на аккаунт), CSV выбранного семестра, средний балл по оценённым предметам, порог сравнения баллов 1–100.
- Mini App: адаптивный обзор, поиск, фильтр «Ниже порога», сортировка, карточки работ и посещаемости, настройки и удаление аккаунта.
- Зашифрованные Fernet-токены в SQLite, проверка HMAC Telegram `initData` с TTL 1 час, изоляция пользователей и кэш последних баллов при сбое БРС.
- Надёжная очередь уведомлений: недоставленные события остаются в SQLite для повторной отправки. При аварии между отправкой и фиксацией доставки возможен повтор сообщения (at-least-once).
- Long polling: для самого бота входящие порты и публичный адрес не нужны.

## Сразу посмотреть дизайн

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
DEMO_MODE=true .venv/bin/python -m brsy
```

Открыть `http://127.0.0.1:8000`. В Windows вместо `.venv/bin/python` используется `.venv\Scripts\python.exe`.

В деморежиме все баллы вымышлены, реальные токены не принимаются, настройки меняются только до перезагрузки страницы. `DEMO_MODE=true` несовместим с заданным `BOT_TOKEN`. Демо никогда не подставляется при ошибке реального API.

## Запустить своего бота

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи **токен Telegram-бота**. Это отдельный секрет, не студенческий токен БРС.
2. В корне проекта:

```sh
cp .env.example .env
chmod 600 .env
.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

3. В `.env` укажи `BOT_TOKEN` и сгенерированный `ENCRYPTION_KEY`. Оставь `DEMO_MODE=false`. Ключ генерируется **один раз**: он нужен при каждом запуске и восстановлении базы.
4. Запусти `.venv/bin/python -m brsy`, открой **своего** бота, отправь `/start`, затем студенческий токен БРС. Бот проверяет его запросами БРС и пытается удалить сообщение с токеном. Если удаление невозможно, сообщение останется в чате — его можно удалить вручную.
5. Бот сам зарегистрирует команды в меню Telegram. `MINI_APP_URL` можно пока оставить пустым — все основные функции доступны в переписке.

Не запускай два экземпляра бота с одной базой или одним BOT_TOKEN. Приложение рассчитано на один процесс. Не запускай Uvicorn с несколькими workers.

## Raspberry Pi: Docker (предпочтительно)

Используй 64-разрядную Raspberry Pi OS и уже установленный Docker с Compose. Образ собирается на самой Pi из официального `python:3.12-slim`; поддержка ARM64 обеспечивается базовым образом. Сборка и потребление памяти **на физической Raspberry Pi пока не проверены**. Для старых 32-разрядных Pi доступность Python wheels может отличаться.

Скопируй проект и заполни `.env`, как выше. Если Python пока не установлен, ключ можно сгенерировать контейнером:

```sh
docker run --rm python:3.12-slim sh -c 'pip -q install cryptography && python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"'
docker compose up -d --build
docker compose logs -f --tail=50
```

После перезагрузки Pi контейнер поднимется автоматически, если включён Docker daemon. База хранится в Docker volume `brsy-data`. `docker compose down` сохраняет её; `docker compose down -v` уничтожает. Проверка: `curl http://127.0.0.1:8000/healthz`.

По умолчанию опрашиваем каждого пользователя раз в 300 секунд, максимум четыре запроса одновременно. Интервал меняется через `POLL_INTERVAL`, минимум — 60 секунд. Пользователи с отклонённым токеном исключаются из фонового опроса до переподключения; в приложении отображается причина. Автоматические и ручные проверки используют одну точку отсчёта и общую очередь событий.

## Без Docker: systemd

1. Установи `python3`, `python3-venv`, создай системного пользователя `brsy` и размести проект в `/opt/brsy`.
2. Создай `/opt/brsy/.venv`, установи `requirements.txt` и заполни `/opt/brsy/.env`. Файл должен читаться пользователем `brsy`, права — `600`. Сам код можно оставить под владельцем root.
3. Скопируй `deploy/brsy.service` в `/etc/systemd/system/brsy.service`, затем:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now brsy
sudo journalctl -u brsy -f
```

База создаётся в `/var/lib/brsy`. Сервис имеет доступ на запись только в свою рабочую директорию данных. Настройки путей в `.env` для systemd не должны переопределять значения из unit-файла.

## Оформление Mini App

Монохромный интерфейс: графитовые поверхности, серебристые градиенты, круг среднего балла и плавающая навигация на телефоне. Тёмная тема включена по умолчанию. Кнопка в шапке переключает тёмную/светлую тему; в настройках также есть автоматическая тема по системе. Выбор сохраняется локально на устройстве и не отправляется на сервер. Анимации учитывают `prefers-reduced-motion`.

## Подключить Mini App в Telegram

Mini App требует публичный **HTTPS** URL твоего сервера. Для дома за NAT нужен туннель к `127.0.0.1:8000` или reverse proxy на сервере с публичным адресом. Постоянный домен удобнее временного URL туннеля. Пример Caddy — `deploy/Caddyfile.example`.

1. Настрой HTTPS-прокси/туннель до приложения. У самого Python-сервера оставь `HOST=127.0.0.1`; Docker уже публикует порт только на loopback.
2. Запиши `MINI_APP_URL=https://твой-домен` в `.env` и перезапусти бота: `docker compose up -d --force-recreate`.
3. В боте появится кнопка «Открыть БРС рядом», а в меню — «Моя БРС». Бот задаёт menu button автоматически. При желании также настрой Main Mini App через BotFather, указав тот же HTTPS URL.
4. Входи через кнопку в Telegram: обычный браузер не имеет подписанного `initData` и не получает личные данные. Через час переоткрой приложение для новой сессии.

Интерфейс и API обслуживаются одним сервером, CORS и отдельный фронтенд-хостинг не нужны. Telegram Web должен иметь возможность встраивания; CSP разрешает фреймы `web.telegram.org` и поддомены `telegram.org`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Подключение или главное меню |
| `/connect`, `/instruction` | Инструкция и ввод нового токена |
| `/cancel` | Отмена ввода |
| `/grades`, `/refresh` | Баллы / проверка обновлений |
| `/semesters` | Выбор семестра |
| `/history` | Последние 15 изменений |
| `/settings` | Уведомления и настройки |
| `/target 80` | Порог сравнения баллов |
| `/export` | CSV текущего семестра (в Mini App — выбранного) |
| `/logout` | Удаление данных с подтверждением |
| `/help`, `/privacy` | Команды и информация о данных |

## Состояние интеграции с БРС

Адаптер использует существующие read-only маршруты `api/v1/student/`: корень, `semester_list`, `discipline/subject?id=…`, `discipline/journal?id=…`; токен передаётся параметром `token`, семестр — `SemesterID`.

Контракт исследован по исходникам открытого [клиента MihaxXx/grade_app](https://github.com/MihaxXx/grade_app/blob/master/GradeAPI/API.cs); его код в проект не включён. Во время разработки проверен живой ответ `403 {"code":"403","message":"Token is broken."}` без токена. **Авторизованные запросы пока не проверены: действующего студенческого токена нет.** Схему и поведение нужно подтвердить с реальным аккаунтом; при изменении формата адаптер показывает ошибку, а не подменяет баллы. Это свой аналог, полное совпадение со всеми неизвестными функциями старого бота не заявляется.

Средний балл — арифметическое среднее `Rate` оценённых предметов выбранного семестра; `null` не считается нулём. `MaxCurrentRate` показывается отдельно. Порог сравнения не является правилом допуска, зачёта, стипендии или итоговой оценки.

## Проверки

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check web/app.js
```

Тесты не требуют токенов и не обращаются в БРС или Telegram: проверяют подпись/срок `initData`, изоляцию пользователей, шифрование/удаление данных, изменения баллов и очередь, форматы upstream API, ошибки и API приложения.

## Данные и обслуживание

- Не публикуй `.env`, базу и резервные копии. Токен в API БРС передаётся в query string согласно существующему контракту; HTTP-логи приложения отключены. Не включай debug-логи HTTPX и логирование authorization headers на прокси.
- Копируй SQLite через backup API (или при остановленном приложении), а `ENCRYPTION_KEY` храни отдельно и безопасно. Простое копирование активного `.sqlite3` без WAL может потерять данные.
- `/logout` удаляет данные из рабочей базы каскадно. Файлы резервных копий контролирует владелец сервера; их срок хранения нужно определить отдельно. В WAL/на носителе могут оставаться старые блоки до перезаписи.
- Токены шифруются на диске, но сам сервер имеет доступ к ключу. Не передавай свой токен чужому экземпляру бота, владельцу которого не доверяешь.
- `requirements.txt` фиксирует версии прямых и транзитивных runtime-зависимостей, проверенные в этой среде. Перед обновлением зависимостей повтори тесты.

Сведения о Telegram Mini Apps и алгоритм HMAC: [официальная документация Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
